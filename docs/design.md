# 후쿠오카 여행 플래너 앱 — 설계 문서

작성일: 2026-11-18 · 상태: 초안(승인 대기)

## 1. 목적과 배경

- 2026-12-31(목) 저녁 출발 → 2027-01-03(일) 오후/저녁 귀국, 3박 4일 후쿠오카 여행.
- 여행 기간에만 쓰는 **일회용 모바일 앱**. 지도 위에서 일차별 루트, 장소별 일정·메모를 한눈에 보고, 현지에서 발견한 맛집·장소를 직접 핀으로 추가한다.
- 사용자 1명, 기기는 **안드로이드(크롬)**. 동행자 공유 없음.
- 장소 목록은 아직 없다. 다음 주에 동행자와 정한 뒤 **앱 안에서 직접 입력**한다(Claude에게 목록을 주고 일괄 입력도 가능).

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 후쿠오카 중심 지도 + 일차 탭(전체 / 12/31 / 1/1 / 1/2 / 1/3)으로 루트와 장소를 본다.
- 장소를 앱 안에서 추가·수정·삭제·순서 변경, 일차 지정, 후보 → 일정 편입이 가능하다.
- 부가 탭: 준비물 체크리스트, 교통 메모, 지출 기록.
- 홈 화면 아이콘으로 앱처럼 실행한다.

**비목표**
- 다중 사용자, 로그인, 서버 동기화.
- 앱 안에서의 실제 경로 안내(구글맵 앱으로 넘긴다).
- 지도 타일 오프라인 저장(현지 eSIM/포켓와이파이 사용 전제).
- 앱스토어 배포.

**실패 조건(동작하더라도 실패로 보는 것)**
- 여행 중 입력한 데이터가 사라진다.
- 현지에서 화면이 작거나 조작이 번거로워 결국 구글맵/메모장으로 돌아간다.
- 인터넷이 약할 때 일정·메모조차 열리지 않는다.

## 3. 제약

- 비용 0원, API 키 없음.
- 연말연시(正月) 기간: 1/1~1/3 휴무 가게 다수, 신사 참배 인파, 1/2 하츠우리 세일 → 장소마다 연말연시 영업 정보를 따로 기록할 수 있어야 한다.
- 화면: 안드로이드 폰 세로 화면 기준, 한 손 조작, 글자 넉넉하게(본문 16px 이상).
- UI 언어: 한국어.

## 4. 방식 검토 (Approaches)

| 방식 | 장점 | 단점 | 결정 |
|---|---|---|---|
| **PWA (정적 HTML/JS + Leaflet + OSM), 홈 화면 설치** | 무료, 설치 즉시, 구성 자유, 오프라인 일부 가능 | 처음 제작 필요 | **채택** |
| Google My Maps | 즉시 사용 | 일차 탭·시간표·지출 등 UI 커스텀 불가 | 기각 |
| 네이티브 앱 | 완성도 | 빌드·서명·설치 과정 과함(일회용 목적과 상충) | 기각 |

사용자가 PWA 방식에 동의함.

## 5. 결정된 사항

### 5.1 화면 구성
하단 메뉴 4개: **🗺 지도 / ✅ 준비물 / 🚇 교통 / 💴 지출**

**지도 화면**
- 상단 탭: `전체` `12/31(목)` `1/1(금)` `1/2(토)` `1/3(일)` `후보`
- 일정 장소: 일차별 색상의 번호 마커(①②③…) + 방문 순서대로 연결선.
- `전체` 탭은 모든 일차를 색상별로 동시 표시.
- 후보 장소: 카테고리 아이콘 마커(맛집/카페/쇼핑/관광/기타). `후보` 탭은 후보만 표시. 다른 탭에서도 후보는 흐리게 함께 표시(초안 — 빌더 판단 가능).
- 숙소: 항상 표시되는 별도 마커.
- 우하단 버튼: 내 위치, 장소 추가(＋).
- 하단 시트(끌어올림): 선택한 일차의 시간순 일정 목록. 항목을 누르면 지도가 해당 마커로 이동하고 카드가 열린다.

**장소 카드**
- 이름, 일차·예정 시간, 머무는 시간, 카테고리
- 메모(예약번호, 추천 메뉴 등 자유 텍스트)
- 영업시간(자유 텍스트) + 연말연시 영업 여부(영업 / 휴무 / 미확인)
- 버튼: `구글맵 길찾기`(좌표 기반 딥링크), `수정`, `삭제`

**장소 추가**
- 지도 길게 누르기 → 해당 좌표로 추가 폼
- 현재 위치로 추가
- 이름 검색으로 좌표 찾기(무료 지오코딩)
- 폼 항목: 이름, 카테고리, 일차(미지정=후보), 시간, 메모, 영업정보
- 일정 순서 변경, 후보 → 특정 일차로 편입

### 5.2 부가 탭
- **준비물**: 체크리스트, 항목 추가/삭제, 체크 상태 저장. 기본 항목 몇 개 미리 채움(여권, 엔화, eSIM, 충전기, 보조배터리, 상비약).
- **교통**: 메모 카드 목록(제목 + 내용, 추가/수정 가능). 기본 카드: 공항↔하카타/텐진 지하철, 니시테츠 버스, 다자이후 가는 법, 연휴 운행 주의.
- **지출 + 정산**: 금액(엔), 항목, 일차, 결제수단(현금/카드), **낸 사람**, **나눌 사람들**(기본: 전원 균등 분할, 체크 해제로 일부만 분할). 일차별·전체 합계, 사람별 부담액, 마지막에 "누가 누구에게 얼마"를 최소 송금 횟수로 표시. 사용자가 입력한 환율로 원화 환산. 동행자 이름은 설정에서 입력. 앱 사용자는 1명(대신 기록)이다.

### 5.3 데이터·배포
- 모든 데이터는 기기 로컬 저장(localStorage 또는 IndexedDB).
- **백업 내보내기/불러오기(JSON 파일)** 제공. 같은 화면에 **전체 초기화** 버튼(한 번 더 확인 후 모든 데이터 삭제, 테스트 데이터 정리용 — 2026-11-18 사용자 요청). Claude가 장소 목록을 일괄 입력할 때도 이 불러오기 형식을 사용.
- 지도를 제외한 화면은 오프라인에서도 열림(서비스 워커로 앱 파일 캐시).
- 호스팅: **GitHub Pages**(사용자 계정, 확정). 사용자가 직접 push한다. 안드로이드 크롬 "앱 설치/홈 화면에 추가"로 설치.

### 5.5 진행 방식 (사용자 요청: 한 번에 만들지 않고 단계별로)
- 단계마다 **만들기 → Claude가 모바일 화면 크기로 직접 확인 → 사용자가 폰에서 확인·승인 → 다음 단계** 순서로 진행한다.
- 1단계부터 GitHub Pages 배포·폰 설치까지 끝까지 연결해 두고, 이후 단계는 기능을 덧붙인다.
- 지도: Leaflet + OpenStreetMap 타일, 초기 중심 후쿠오카(하카타~텐진).

### 5.4 검토 후 정한 사항 (Claude 판단 — 사용자 확인 대상)
- **일정 순서**: 일차 안의 순서는 **수동 순서(order)**가 기준이다. 번호 마커·연결선·하단 시트 모두 이 순서를 따른다. 시간은 선택 입력이고 표시만 한다. 순서를 바꿔도 시간은 자동으로 바뀌지 않는다.
- **백업 불러오기**: 기본은 **병합**(장소마다 고유 ID, 같은 ID는 덮어쓰기, 새 ID는 추가). "전체 교체"는 별도 옵션으로 둔다. 불러오기 직전에 현재 데이터를 자동 백업하고, 불러올 항목 수를 미리 보여준다.
- **숙소**: 숙소는 장소 종류 중 하나이며 **묵는 날짜(박)**를 지정한다. 한 곳이면 전 일차에 표시하고, 여러 곳이면 해당 날짜 탭에만 표시한다.
- **시작 데이터**: 실제 장소 목록은 배포 파일에 넣지 않고 폰에서 불러오기로 넣는다. 저장소가 공개여도 일정은 노출되지 않는다.

### 5.6 동행자 공유 (2026-11-18 확정: A안)
- 여자친구도 같은 주소로 설치해 사용한다. 데이터는 기기별로 저장된다.
- 공유는 **백업 파일 주고받기**(A안): 5단계에 "공유하기" 버튼(Web Share API로 카톡 등에 JSON 파일 전송) 추가. 받은 쪽은 불러오기(병합).
- 실시간 동기화(B안, 클라우드 DB)는 하지 않는다.
- 지출·정산은 한 사람 기기에 기록하는 것을 권장(중복 입력 방지).
- 여자친구 기기 종류(iOS/Android): 미확인.

### 5.7 홈 탭 (2026-11-18 추가)
- 하단 메뉴 5개: **홈 / 지도 / 준비물 / 교통 / 지출**. 앱은 항상 **홈에서 시작**한다.
- 상단: 제목 `후쿠오카`, 일정 `2026.12.31(목) – 2027.1.3(일)`. D-day 표시는 하지 않는다(사용자 결정).
- **메인 사진**: 포토카드 느낌(흰 테두리, 둥근 모서리, 옅은 그림자), 화면 폭에 맞춘 세로 비율.
- **썸네일 슬라이드**: 메인 사진 아래 가로로 넘기는 작은 사진 줄. 썸네일을 누르면 그 사진이 메인 사진으로 바뀐다.
- 기본 사진 1장(`사진.jpeg`)을 앱 파일에 포함한다. 저장소가 Public이라 사진이 공개되는 것을 사용자가 수락함. 위치정보 등 EXIF 메타데이터는 제거하고, 화면용으로 크기를 줄인다.
- **사진 추가 버튼**: 썸네일 줄 끝의 `+` 칸. 갤러리 업로드·세로 모아보기 기능은 이후 단계에서 구현한다(이번에는 위치만 잡는다).

## 6. 빌더에게 맡기는 것
- 프레임워크 사용 여부(바닐라 JS 권장, 빌드 단계 없이 정적 파일).
- 색상·아이콘 세부 디자인, 다크모드 여부.
- 지오코딩 서비스 선택과 결과 표시 방식.
- 저장소 종류(localStorage/IndexedDB)와 데이터 스키마 세부.
- 순서 변경 UI(드래그 또는 위/아래 버튼).

## 7. 미확정 사항
- 숙소 위치: 미정(다음 주 결정 후 입력).
- 일차별 장소 목록: 미정(다음 주 결정 후 입력).
- 환율: 여행 직전 사용자가 입력.
